# Uno234: current direction

Updated 2026-10-23. **Uno234 is one activity with two interchangeable input panels: Counts and Perform.** The current activity is named **Uno234**. **Rhythm Walk** is reserved for an eventual continuous gameplay mode; it is not a current response mode. Existing prototype URLs, source directories, and preference keys retain their historical names for compatibility. Count Writing is the historical name of Write Counts; the original performance-only Rhythm Walk prototype is now Tap Rhythms. This decision supersedes the Write/Tap/Both selector, descriptions of separate activities and the earlier Count Writing-first sequencing. Saved Tap opens Perform; saved Write or Both opens Counts. The legacy mode preference remains a compatibility detail. It does not authorize production publication.

Counts and Perform place a continuous, readable horizontal score above their input controls. A notation overview appears only when the passage overflows and supports pointer/keyboard navigation. Count targets stay 44px; entry follows the active count without moving the page. Perform uses closer measure spacing when written counts are hidden, keeping multi-measure exercises on one row so the pad follows the score. Each panel retains its scroll position; selecting Counts reveals the first empty count. Perform resets to the beginning for count-in and follows the audio clock through overflowing notation, keeping the current position about one-third across the viewport with upcoming music to the right. Scrolling advances steadily across each measure, so barline spacing cannot cause a burst of speed during a short final note; performance input never changes the scroll position or pace. The overview tracks the visible range; completion or interruption stops following, and retry starts at the beginning. Choose rhythms and Next Exercise share the row above the score. Counts / Perform selects the input panel; Feedback opens the contextual ratings and review below the score. The mobile counting palette docks inside the workspace when space permits and stays in normal flow on short screens. Other exercise settings collapse below, with pending changes still explicit. Perform shows the performance controls and review graph. See the [responsive layout contract](responsive-layout-audit.md).

The **Choose rhythms** dialog uses the same visual language as tuNotes: an **Uno’s Choice / UIL Sight Reading / Custom** pill above a single column of wide, compact preset cards. Cards show allowed notation, meters and enabled extras; each pencil opens Custom using that preset as its base. UIL cards preview complete figures for the selected General/Percussion scope. **Use preset** saves the pending configuration; Cancel, × and Escape discard the draft. The available configurations are: **Uno1–Uno5**, UIL I–IV General/Percussion note-only figure practice, or **Custom**. V–VI, cut time and within-exercise meter changes are deferred. **Custom** edits ingredients and musical constraints. Normal practice always generates; fixed rhythms live only in explicitly enabled developer/testing access (`?testing=1` or a valid `?fixture=` link). Level changes are pending until **New exercise**, retaining the current score and responses. Musical edits retain source attribution as customized; length, tempo, mode, counting system and Tap/Tap + Hold are independent. Reload restores the configuration, never a saved fixture mode.

The Uno configurations are cumulative, with independent 1–4 measure length:

| Level | Musical configuration |
| --- | --- |
| Uno1 | 4/4; quarter notes, quarter rests and half notes only; no ties or syncopation. |
| Uno2 | 4/4; whole, half, quarter and eighth notes; quarter and half rests; no ties or syncopation. |
| Uno3 | Uno2 plus 2/4 and 3/4, dotted-half and dotted-quarter notes, and ties. |
| Uno4 | Uno3 plus 6/8, sixteenth notes, eighth rests, syncopation, sounded eighth triplets and dotted-eighth notes. |
| Uno5 | All currently supported ingredients (also sixteenth and dotted-quarter rests), ties, syncopation and unintuitive notation in all four meters. |

Generated exercises contain at least four sounded attacks (ties count as one attack), start with a sounded note and cap total rest duration at 15% of the exercise. A one-measure Uno1 exercise therefore uses four quarter notes. These automatic limits can omit longer notes or rests in short exercises; impossible custom pools show a validation message. UIL note-only figure profiles remain unchanged. Saved Uno1–Uno4 selections migrate to Uno2–Uno5.

Custom offers five independent, notated sixteenth groupings: four sixteenths, eighth–sixteenth–sixteenth, sixteenth–sixteenth–eighth, sixteenth–eighth–sixteenth, and dotted eighth–sixteenth. Each is a complete beat-aligned figure in simple meters. No frequency controls are added.

These are Uno practice configurations, separate from UIL criteria. Each exercise draws one selected meter and uses only its compatible ingredients: whole notes and whole rests require 4/4; dotted halves are skipped in 2/4; half/whole values, sixteenths, dotted eighths and triplets are skipped in 6/8. “Everything” does not expand the supported repertoire.

## Decisions carried forward

- Performance **How to play** is selectable in shared settings: Tap (default) or Tap + Hold. Both reuse canonical sounding chains and raw capture. Attempts retain the choice/policy used; completed reviews do not change when preferences do. Tap reviews attacks only; Tap + Hold adds actual duration bars and provisional release/articulation feedback. See [performance policy](performance-prototype.md#selectable-tap--tap--hold).

- One shared exercise/configuration with freely switchable Counts and Perform input panels; writing then performing is optional. Switching preserves the exact exercise; Next replaces it and clears both responses.
- Musical source is a flat written-event sequence with exact fractional time, not stored base-twelve positions. The twelve-subdivision beat coordinate is derived; ties join written members into one sounding attack. Thirty-second notes and quintuplets remain out of scope. Domain support for other values does not imply UI support.
- Default generated length is two measures, configurable 1–4. 6/8 uses six numbered eighth counts, grouped 123 / 456, and two dotted-quarter performance pulses.
- Each written rest is a separate inferred unit. Rest and duration indications are independent evidence. All exposed count positions are required; optional-subdivision and endpoint grading have been removed.
- Performance capture ends at the written ending plus 300 ms and any positive fixed calibration offset. Slower playing does not extend the deadline; unfinished notes remain part of the feedback.
- Timing normalization estimates one constant, input-specific offset and reuses it for the tab session. Manual tap-along is the fallback; retries do not refit the offset or stretch time. Raw evidence is retained.
- Browser defaults survive reloads; linked counting and edits stay session-only until explicitly saved as defaults. Exercise responses/results do not survive reloads. Calibration uses a separate session store. Prototype routes are compatible entry points, not a production release.

## Counting correction cycle

Counting and performance results use the Feedback pill beside Counts and Perform. Check and completed performances open Feedback automatically; its links return to Counts for corrections. Level, Edit and Next Exercise share one row above the score. Each applicable evaluator item earns one point: count tokens individually, and rest/duration evidence once per inferred unit, including cross-bar ties. Not-applicable items are excluded. Correctly leaving a sounded unit unmarked as a rest earns its existing rest-identification point; correctness criteria are unchanged.

Counting uses an independent 0–5 bone scale: below 20% earns 0, ≥20/40/60/80% earns 1/2/3/4, and only all applicable points correct earns 5. Integer point totals determine tiers before display rounding; Tap and Tap + Hold reward policies are unchanged. Zero applicable points have no percentage or bone rating. Unchecked exercises are unscored. Percentages are rounded only for display.

Check captures the answer and evaluation. Subsequent edits retain that confirmed score and mark changed aspects as awaiting Check Again; no grading runs on input. Purple dashed borders indicate unresolved aspects, dotted count-box borders indicate edits awaiting check, and an outer solid teal outline identifies editing focus. There are no letter annotations; the palette explains count, rest and duration independently, including multiple problems at one position. Selecting a position explains the relevant aspects without supplying answers. Feedback links navigate through the existing horizontal workspace. Reassessment replaces the snapshot, and completion offers Next Exercise while allowing review. Both keeps counting and performance results independent. Exact evaluator evidence is available in Feedback → Details → Technical counting evidence.

Regression entry points: `node scripts/counting-corrections-browser-check.mjs`, `npm run test:counts:browser`, and `node scripts/responsive-workspace-browser-check.mjs` after a full build; set `TUNO_BROWSER=firefox` for Firefox. Physical-device and screen-reader acceptance remain separate.
