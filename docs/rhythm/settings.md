## What works now

Shared and mode-specific preferences normally save automatically in this browser through localStorage. A valid counting link overrides only counting before the first exercise; linked counting edits remain session-only until **Save as my defaults**. Unrelated saves preserve the recipient’s counting defaults. Responses and results are kept only for the current exercise in memory; reload starts with blank responses. **New Exercise** uses the same generation action as practice’s Next exercise, applies the current settings, clears both responses/results and returns to practice. Writing modes focus the first count; Tap Rhythms does not. Invalid configurations disable both buttons and keep the current answer. The action and automatic-save explanation appear above the active controls.

- **Time signatures:** check any of 2/4, 3/4, 4/4 and 6/8. Each Next/New Exercise draws one selected meter for the entire passage; pending changes preserve music and answers. Checking a simple meter enables quarter notes; checking 6/8 enables eighth notes. Other ingredients stay checked and are skipped when incompatible with the chosen meter. See [meter rules and examples](meters.md).
- **Vocabulary and offbeat display:** numbers `1 e & a` or syllables `1 ta-te-ta`, plus &/+. All changes are pending until New exercise; active tokens/results are not translated or cleared. Type t then a/e for ta/te, l for la and i for li. 6/8 labels stay numeric; choices can still be saved for subsequent simple-meter exercises.

- **Exercise length and allowed ingredients:** generated single-meter practice (2/4, 3/4, 4/4, 6/8) defaults to 4/4 and 2 measures (configurable 1–4) with quarter/eighth/half/dotted-quarter notes and quarter/eighth/half rests enabled. Dotted-quarter rests are unchecked by default. Changes preserve the current answer and apply on Next exercise. Empty pools and configurations that cannot fill a selected meter explain why and disable Next; see [generation decisions](practice-loop.md).
- **Allow unintuitive notation:** off by default. Quarter and half rests start on whole beats; half rests may start on any whole beat where they fit. Enable this to permit offbeat longer rests and selected dotted-quarter rests in simple meters. Simple-meter dotted rests stay selected but are skipped without the opt-in. In 6/8 dotted-quarter rests fill either three-eighth group normally; rests crossing the group boundary need this opt-in, while half notes/rests are skipped in generated 6/8. Changes apply on Next and preserve the current answer.
- **Ties and Syncopation:** independent, both off by default. Ties permit one chain of 2–3 selected written note segments, within or across measures. Syncopation permits at most one off-pulse sounding attack per measure sustained across the following pulse (quarter in simple meters, dotted quarter in 6/8); sounds ending at that pulse remain available when off. Patterns with no eligible candidates are skipped; only an unfillable passage blocks generation. Changes apply on Next, retaining the current answer. See [counting, generation and fixture decisions](ties-syncopation.md).
- **Layout:** measures wrap automatically; explicit wrapped testing fixtures force one measure per system. Unit indication state survives wraps. Dense writing measures scroll notation and answers together; hidden-count performance retains its compact score.
- **Level:** one shared header selector for Uno1–Uno4, qualified UIL I–II note-only generation configurations and Custom. The cumulative [Uno configurations](README.md) add the requested vocabulary and constraints; Uno4 enables all supported ingredients and unintuitive notation. III–VI remain selectable for inspection, with clear reasons and disabled application. Selecting a supported level updates pending settings immediately; New exercise generates and clears both responses. Musical changes retain source attribution as customized. Length, tempo, response mode, counting system and Tap/Tap + Hold preserve the level. Customize… uses symbol toggles in aligned whole/half/quarter/eighth/sixteenth rows, with note variants beside each other and corresponding rests in the second column. Whole rests are opt-in in 4/4. It edits the musical settings and length; reapplication restores controlled fields. See [reviewed mappings and capability gaps](uil-presets.md).
- **Testing fixtures:** fixed rhythms live behind explicit `?testing=1` or valid `?fixture=` access. The developer/testing selector replaces the exercise for reproducible debugging. New exercise always returns to generated practice. Saved fixture selections never reopen ordinary learner visits in testing mode.
- Rhythm Walk / Settings navigation, keyboard focus on the page heading, browser back/forward, direct settings links and expandable groups.

Navigation and mode switches preserve the current exercise, saved symbols/markings, and both evaluations. Shared Level, Customize… and New exercise controls appear above the response section; Mode appears beneath the score. Level and generation actions remain available on Settings. Write Counts owns count presentation and conventions; Tap Rhythms owns tempo, metronome and timing calibration. Both exposes either response without prerequisites, with optional Perform this exercise and Show written counts during performance controls. See [shared ownership and persistence](unified-activity.md).

Tap Rhythms supports 40–180 pulse BPM (default 80), an exercise-metronome toggle, a one-bar audible count-in and Calibrate opening a timing dialog. Tempo appears in the score’s top left, with quarter-note pulses in simple meters and dotted-quarter pulses in 6/8. Metronome during exercise lives under Performance on Settings. The session offset, automatic estimation and manual fallback follow [timing calibration](timing-calibration.md). Broader inactive inventory controls do not disable these implemented behaviors.

The shared version-1 counting contract exposes **Long-note subdivision**, **Dotted subdivision**, **Include rests**, **Show duration line**, **Line placement**, **Internal-count appearance**, **Rest appearance**, **Vocabulary**, and **Offbeat display**. Defaults are long on, dotted off, rests included, visible line beside counts, raised internal counts and parentheses. Line placement does not reset internal appearance. Hidden lines with unchanged appearance suppress duration controls/scoring; omitting rests suppresses rest controls/scoring for every unit.

All counting edits apply on New exercise, including appearance. The current score, evidence and feedback stay intact and the shared summary shows a pending notice. Browser migration preserves meaningful old display choices and uses new subdivision defaults where the dotted convention has no exact equivalent. It explains the change once, writes nested `counting.version = 1` under the existing outer storage key, and preserves unrelated preferences. **Copy counting preferences link** shares all nine selections currently shown as readable `counting.*` query parameters with `counting=1`, including pending edits, with a manual-copy field if clipboard access fails. Links preserve unrelated query parameters and view routing but remove fixture/testing access. Invalid links show a notice and retain saved/default counting. Explicit **Save as my defaults** adopts pending counting without replacing the active exercise; storage failures keep the session isolated. Reloading with the link reapplies its configuration; opening without it restores saved defaults. See the [URL/session implementation contract](counting-schemes-spec.md#counting-urlsession-slice-implemented-2026-10-15).

## Availability and scope

The page distinguishes **Available now**, **Not available yet**, **To be decided**, and **Outside this release**. Unavailable inputs are natively disabled with readable labels and explanations; their values are not serialized or passed to an exercise engine. Open numerical values are blank instead of receiving invented defaults. Current fixed behavior and confirmed future defaults are shown where applicable. Unknown checkbox defaults use an indeterminate indicator; no choice is implied.

The two planned vocabulary lists are ordinary independent checklists, not three-state controls. Both remain empty and inactive: the limited practice generator uses the separate active ingredient controls above, and these broader progression lists are future settings. When enabled later, the progression goal must contain the starting vocabulary. Meter selection and changes within a passage are separate controls; a UIL preset must never gate meter selection.

Adding a placeholder does not approve a feature, teaching policy, exact option set or release milestone. Thirty-second notes and quintuplets remain out of scope under the owner's later decision. Internal scoring algorithms are documented as unresolved policies, not presented as invented student-adjustable formulas.

## Implementation boundary

The Customize dialog mirrors the header Level selector and applies the same pending configuration in either location. Measures is a single-choice segmented control; meters, notation ingredients, Unusual Notation, Ties and Syncopation are independent toggles with selection marks. Whole/half noteheads stay hollow on either background. Note variants and corresponding rests share compact, separated rows. Initial focus goes to Level; Escape returns focus to Customize. Generation errors remain visible without ready-state or instructional filler.

- [settings-catalog.ts](../../src/apps/rhythm-walk/shared/settings-catalog.ts) is the review inventory with stable identifiers, grouping and source sections. It is not a settings persistence schema or a music model.
- [settings.ts](../../src/apps/rhythm-walk/shared/settings.ts) renders available controls and inactive options with shared UI primitives.
- [main.ts](../../src/apps/rhythm-walk/main.ts) coordinates the shared lifecycle; [plan-editor.ts](../../src/apps/count-writing/plan-editor.ts) projects one exercise-owned plan/answer into measure views. The music core alone supplies requirements and evaluation.
- Musical source and checking still use the [canonical model](music-model.md). Do not infer that disabling a UI placeholder means the underlying model cannot represent that rhythm, or that model support means an exercise can be rendered/graded.

When implementing a setting, replace its placeholder with a real state contract, connect it to the appropriate activity, and add behavior tests. Resolve open defaults before enabling them. Enforce starting⊆goal and valid generation only when that functionality exists; do not simulate a working generator by storing ineffective selections.

## How to play

Performance settings include Tap (default) — “Tap when each note starts.” — and Tap + Hold — “Hold each note for its length. Release for rests.” The saved `playStyle` applies to Tap Rhythms and Both; it preserves the current exercise, configuration, written answer and completed interpretation. It locks during count-in/capture and calibration. Retry snapshots the current selection. No learner tolerance controls are added; see the [provisional performance policy](performance-prototype.md#selectable-tap--tap--hold).
